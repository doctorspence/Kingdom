## The project in one paragraph
KINGDOM (working title) is a dark fantasy co-op action RPG in Godot 4.7.2 (GDScript), host-and-play for 1-10 players, Souls-style combat plus a WoW-style hotbar. The owner has no coding experience.

**Stealth stage 1, crouch (2026-11-25, `main`, uncommitted when written):** Ctrl or C (gamepad: click the left stick) toggles a crouch: 2.2 m/s (a gently tilted stick is slower), `Crouch_Idle` / `Crouch_Fwd`, stands you up when you roll, jump, sprint, block, drink, cast, climb, get hit or go down (`_set_state` clears it on leaving MOVE), and can't be used when overloaded or in the river. A swing from a crouch drops you back into it only if it hit nothing. "Walk" keeps its action but has no key now. `net_stealth` (0-4) is shared and `Player.seen_mult()` / `heard_mult()` exist, and enemies now use them (stage 2, below). **Stealth stages 2-4 (2026-11-25, `main`, uncommitted when written):** enemies no longer spot you instantly. Each calm enemy keeps an awareness meter per player (host only): sight fills it faster the closer you are (2.5 s at the edge of its range, 0.2 s up close), a noise fills it in 0.6 s, and it drains after 1.5 s of nothing. At 0.5 it turns SUSPICIOUS (new last entry of `Enemy.State`): grey "?", draws its weapon, looks toward you, walks over after 1 s, and gives up (back to its post) when the meter falls under 0.25. Full: red "!" then `_notice` as before. Any blow means a fight at once. Bosses, ambushers and RETURN keep the old instant spotting. Crouching shrinks what they see and hear (stage 1 numbers). The first blow on an unaware or suspicious enemy is a **sneak attack** (weapon `sneak_multiplier`, always a crit, x2 balance damage, "Sneak attack"; named rares capped x1.5, bosses none), arrows and Arcane Bolt / Shield Throw included; any hit from **behind** does x1.5 (larger of the two, no stacking). While crouched an **eye** (drawn in code, `game/ui/stealth_eye.gd`) shows above the health bar: closed, half open grey, open red. Details and deviations: end of `STEALTH_PLAN.md`. Checks: `enemy_check`, `combat_check`. Not playtested by hand.

## Things to know
- **Checks:** run one with `--headless --script res://tests/run.gd -- <name>` (README.md). Names: movement, combat, moves, enemy, death, loot, class, subclass, boss, camp, gullet, zone, audio, sound, prefs, outpost. Plus the 3-player check `tests/run_net_check.ps1`. Also `save_check`. Run them one at a time (shared port 31499, and timing checks fail under load). If a timing check fails once, rerun it before suspecting a bug.
- **Godot and git paths:** no PATH shortcuts. Godot is in `%LOCALAPPDATA%\Microsoft\WinGet\Packages\GodotEngine.GodotEngine_Microsoft.Winget.Source_8wekyb3d8bbwe\` (use `_console.exe` for output). Git is `C:\Program Files\Git\cmd\git.exe`.
- **Port 31415 is the owner's live game.** Checks use 31499.
- **New `class_name` scripts need registering:** a new file with `class_name` is unknown to the game until Godot rescans (open the editor, or run `--headless --path . --import`). On 2026-11-25 the new `window_lights.gd` wasn't registered, so `day_night.gd` failed, `player.gd` failed with it, and enemies stopped fighting back. After adding one, run the import before playing.
- **Test keys** (F3-F7, Page Up/Down) only work in the editor or a debug build; the exported friends build has them unbound. F1 help hides them there too.
- **`two_handed = true`** must stay in `data/weapons/weapon_executioner_greatsword.tres` and `weapon_lantern_staff.tres`; the editor dropped it once when re-saving. If class or loot checks fail on "two-handed", look there.
- **Editor churn:** opening the project in the editor regenerates `.import` files and rebakes `assets/buildings/*.scn`. Commit it as its own commit.
- **Two sessions at once:** another session may own `game/world/gullet.gd` or the terrain files. Check `git status` first and commit only your own files.
- **Friends build:** `build/Kingdom-windows.zip` was re-exported 2026-11-22 (176 MB; test keys unbound). Re-export after later changes: README.md "Play with friends".
- **Performance:** `Godot --path . --resolution 1920x1080 --script res://tests/run.gd -- perf_zone` prints FPS at 10 fixed spots (options: `nogrow`, `noomni`, `hide:Node,Node`, `only:spot`). Terrain LODs are in `sculpted_terrain.gd`, `distance_cull.gd` and `shadow_budget.gd` are nodes in tithelands.tscn.
- **Commits** use the neutral local identity "Kingdom Dev".
- **Brother Tallow and the acolytes** are unused data (the old Gullet). Keep or delete is an open decision in `PRIORITIES.md` P2.
- **Reusing art:** shared materials are in `levels/common/materials/`, textures in `assets/textures/`, camp props in `levels/tithelands/props/`. Height fog buries underground rooms: only use it where `DayNight` fades it out underground (as the Tithelands does).
- **Seeing a zone without playing:** `Godot --path . --resolution 1280x720 --script res://tests/run.gd -- visual_env` writes PNGs to `%APPDATA%\Godot\app_userdata\Kingdom\shots`.

- **Cloud sessions (Linux, no Windows Godot):** download `Godot_v4.7.2-stable_linux.x86_64.zip` from the godotengine GitHub releases into the scratchpad, run `--headless --path . --import` once, then scripts as usual. Don't commit the `.uid` files the import creates for other people's scripts.
